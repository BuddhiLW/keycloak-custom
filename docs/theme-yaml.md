# `theme.yaml` reference

`theme.yaml` is the only hand-edited file in a tenant theme repo. Everything under
`dist/` and `manifests/` is generated by `kctheme render`.

Unknown fields are a hard error (`KnownFields(true)`), so a typo fails at `validate`
rather than silently rendering the default.

## What you cannot say

There is no field for `parent=`, `styles=`, `import=` or `meta=`. Those live in
`login/theme.properties`, which is projected from the platform-owned
`kc-theme-properties` ConfigMap — see [architecture.md](architecture.md). The absence
is the security boundary, not an oversight.

---

## Top level

| field | required | notes |
|---|---|---|
| `tenant` | yes | `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$`. Becomes a directory name and a ConfigMap suffix. Keycloak's own theme names (`base`, `keycloak`, `keycloak.v2`, `common`, `admin`, `account`, `email`, `login`) are rejected. |
| `scheme` | yes | `dark-only` \| `dark-first` \| `light-only` |
| `template` | yes | `v1` |

### `scheme` in detail

`scheme` selects **which platform `theme.properties` key is projected**, so it is not
purely cosmetic:

| value | platform key | `darkMode` | light override emitted |
|---|---|---|---|
| `dark-only` | `dark` | `true` | no |
| `dark-first` | `dark` | `true` | yes, from the `light:` block |
| `light-only` | `light` | `false` | n/a — the base tokens *are* the light palette |

`dark-only` and `dark-first` share a platform key, so switching between them is a
**content** change. Switching to or from `light-only` changes the projected key and is a
**registration** change: a PR against the repo owning the Keycloak CR, plus a rolling
restart (`theme.properties` is JVM-cached).

`dark-only` exists because emitting a light override for a product that declares
`color-scheme: dark` produces a login page that does not match the app it fronts.

## `tokens` — the palette

All values are 6-digit hex (`#1a2b3c`). Required unless a default is listed.

| field | default | notes |
|---|---|---|
| `bg` | — | page background |
| `surface` | — | card background |
| `surface_alt` | `surface` | secondary surface |
| `border` | — | |
| `text` | — | |
| `muted` | — | |
| `dim` | `muted` | |
| `accent` | — | links, primary button |
| `accent_hover` | — | |
| `accent_ink` | *derived* | label colour **on** the accent. Left empty it is derived as white-or-page-ink, whichever reads better. State it only if the product has a deliberate on-accent colour. Contrast-checked either way. |
| `input_bg` | — | |

`validate` reports WCAG contrast for text/surface, links/surface, and the button label
on the accent.

## `page.gradient`

| field | default | notes |
|---|---|---|
| `kind` | `none` | `none` \| `radial` \| `linear` |
| `tint` | — | required unless `kind: none` |

## `card`

| field | default |
|---|---|
| `radius` | `14px` |
| `padding` | `24px` |
| `shadow` | `0 24px 80px rgba(0, 0, 0, 0.28)` |
| `width` | `440px` |

`radius` and `width` take a single CSS length (`14px`, `2rem`, `50%`); `padding` takes
one or more. `shadow` is restricted to `[0-9a-zA-Z .,()#%-]` — no `;`, `{`, `}`, `:`,
`/*`, `@` or `\`, so it cannot escape its declaration or smuggle an `@import`.

## `control`

Covers the primary button and text inputs, and stops there — error banners, alerts and
the OTP/recovery templates shift between Keycloak minors.

| field | default |
|---|---|
| `radius` | `10px` |
| `input_radius` | `11px` |
| `input_padding` | `13px 14px` |
| `button_padding` | `11px 16px` |
| `font_weight` | `700` (must match `^[1-9]00$`) |

## `font`

| field | default | notes |
|---|---|---|
| `body` | `system-ui, -apple-system, "Segoe UI", sans-serif` | plain font stack |
| `heading` | `body` | |
| `import_url` | *(none)* | **only** `https://fonts.googleapis.com/css2?…`. Leaving it empty keeps the login page free of third-party requests. |

The `import_url` restriction is deliberate: a login page fetching an arbitrary
third-party stylesheet is an injection surface on the one page where credentials are
typed.

## `brand`

Replaces `keycloak.v2`'s own KEYCLOAK wordmark.

| field | notes |
|---|---|
| `wordmark` | product name. Empty leaves Keycloak's stock logo in place. |
| `mark` | 1–2 characters, the glyph inside the accent square. Required when `wordmark` is set. |
| `logo` | optional — overrides the generated lockup with real artwork |

`mark` and `wordmark` are plain text: the lockup is **generated** as an inline SVG and
embedded in the stylesheet as a `data:` URI, so a tenant ships no binary and needs no
extra projected key. Accented Latin-1 letters are allowed (a product named *Ateliê
Lumière* must be spellable); everything structural (`<`, `>`, `&`, `"`, `/`) is not.

### `brand.logo`

| field | required | notes |
|---|---|---|
| `placeholder` | yes | path **relative to `theme.yaml`**, embedded as a `data:` URI. Size-capped. |
| `src` | no | full-resolution artwork the browser fetches. `https` only. |
| `width` | yes | painted box, CSS pixels |
| `height` | yes | painted box, CSS pixels |

Two shapes:

- **Raster** — set both. A tiny placeholder is embedded in the stylesheet and painted
  under the full-resolution file. `theme.css` is render-blocking, so embedding the full
  artwork would delay the very paint it improves; CSS paints the first-listed background
  on top, so the placeholder shows immediately and the real file covers it on arrival —
  no script, no flash of empty space.
- **Vector** — set `placeholder` only. An SVG under the size cap is already final at
  every resolution, so a second layer sharpens nothing, and adding `src` would cost the
  login page a DNS lookup, a TLS handshake and a third origin.

`width`/`height` are required because a raster has no intrinsic size the stylesheet can
consult; guessing reflows the card when the real file lands.

## `light` — only for `scheme: dark-first`

The `prefers-color-scheme: light` override. Same field names as `tokens`, plus
`gradient_tint`. `surface_alt` and `dim` fall back to `surface` and `muted`, exactly as
they do in the base palette.

`accent`, `accent_hover` and `accent_ink` are repeated here rather than inherited
because one accent cannot serve both modes accessibly: `#5b8cff` measures 5.39:1 on a
dark surface and 3.16:1 on white, and every colour that fixes white breaks dark. That
is also why they are not defaulted: inheriting the dark accent would silently ship a
light mode below WCAG AA.

---

## Worked example

A minimal light-only theme — every omitted field takes its default:

```yaml
tenant: acme
scheme: light-only
template: v1

tokens:
  bg: "#f5f7fa"
  surface: "#ffffff"
  border: "#dde3ec"
  text: "#161b24"
  muted: "#5d6b80"
  accent: "#2f6feb"
  accent_hover: "#2458c4"
  input_bg: "#ffffff"

page:
  gradient:
    kind: linear
    tint: "#e7edf8"

card:
  radius: "12px"
  shadow: "0 12px 32px rgba(22, 27, 36, 0.10)"
```

Rendered output for this exact input is committed at
[`testdata/golden/acme/`](../testdata/golden/acme/).
